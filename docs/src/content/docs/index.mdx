<section class="at-section">
  <header data-reveal><span>03</span><h2>What you stop writing</h2></header>
  <ul class="at-points">
    <li data-reveal><h3>Token plumbing</h3><p>The app token is requested when a call needs it. User tokens are refreshed before they expire, validated every hour as Twitch requires, and saved where you choose.</p></li>
    <li data-reveal><h3>Which token goes with which call</h3><p>Each endpoint knows whether it wants the app token or a user's, and whose. <code>moderator_id</code>, <code>broadcaster_id</code> and <code>sender_id</code> default to whoever is acting.</p></li>
    <li data-reveal><h3>Cursors and page sizes</h3><p><code>await</code> a list for one page, <code>for await</code> it for every item. Lists of more than 100 IDs are split, fetched in parallel and merged.</p></li>
    <li data-reveal><h3>Handling 429</h3><p>The rate limit headers are followed for each token, so requests wait their turn instead of failing. What is safe to retry is retried.</p></li>
    <li data-reveal><h3>Reconnect logic</h3><p>WebSocket, webhooks and conduits share one typed <code>on()</code>. Reconnects, resubscriptions, signature checks and duplicate deliveries are handled.</p></li>
    <li data-reveal><h3>Guessing at shapes</h3><p>Every parameter, response and event is typed. Events that come in several shapes narrow when you check their discriminator.</p></li>
  </ul>
</section>
